### 关键参考

- **Python 模型**: `app/models/query/` — `query.py` / `query_rule.py` / `query_field.py`（最小存根）
- **Python 已有实现**: `app/routers/parts.py:250-309` — `get_queries` + `_load_query_rule`（递归读取已实现）

### DB 表结构
```
query(id PK, name, queryrule_id FK, pathdata_queryrule_id FK)
queryrule(qid PK, cond "AND"/"OR", field, type, operator, id, parent_query_rule FK 自引用)
queryrule_values(queryrule_id FK, value, value_order)
query_selects(query_id FK, selects)
querycontext(query_id FK, configurationitemid, serialnumber, workspaceid)
```

### 核心逻辑（对齐 Java PartRevisionQueryDAO.runQuery）
1. 递归遍历 `QueryRule` 树（已实现读取端 `_load_query_rule`）
2. 叶子节点按 `field` 前缀路由:
   - `pm.*` → PartMaster 字段（number/name/type）
   - `pr.*` → PartRevision 字段（version/status/checkInDate/tags/linkedDocuments）
   - `author.*` → 作者字段
   - `attr-TEXT.*` → JOIN InstanceTextAttribute
   - `attr-NUMBER.*` → JOIN InstanceNumberAttribute
   - ... 共 8 种 InstanceAttribute 子类
3. 非叶子节点按 `condition` AND/OR 组合子谓词
4. SQLAlchemy Core 或 raw SQL 实现（不用 JPA Criteria API）

### 需要实现
- POST 保存端点: 接收 QueryDTO → 递归写入 queryrule 树 + selects + orderBy + contexts
- POST 执行端点: 接收 QueryDTO → 编译为 SQL → 返回 `List[PartRevisionDTO]`
